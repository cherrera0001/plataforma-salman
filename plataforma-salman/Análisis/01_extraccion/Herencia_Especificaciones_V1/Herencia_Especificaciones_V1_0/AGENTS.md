# Reglas para agentes del proyecto

Primero leer 00_ENTREGA.md, maestro/M01.md, maestro/M17.md, sdd/constitucion.md y la feature activa. Esta entrega desarrolla especificaciones: no autoriza construcción, gastos o producción por si sola. Para implementar hace falta orden aprobada.

Mantener IDs 153 originales. Elegir feature por directorio manifiesto y por mecanismo comprobado de la versión de Spec Kit instalada; una rama Git no garantiza contexto de feature. No inventar comandos de integración ni usar contexto de otro repositorio. Código del Grupo Salman separado de VinculaTerritorio.

Respetar spec, datos, contratos y tests. Antes de implementar, resolver decisiones realmente bloqueantes; no inventar políticas, credenciales ni aprobaciones. Trabajar con datos sintéticos. No enviar mensajes, activar anuncios, pagar, facturar o cambiar cuentas reales sin autorización específica.

Cada cambio entrega diff/commit, versión del spec, salida real de pruebas, limitaciones, costos y plan de recuperación. No marcar casos como ejecutados si sólo fueron escritos. No representar varios roles secuenciales como subagentes paralelos reales. La revisión de esta entrega fue consistencia documental propia, no auditoría independiente.

Cambios de esquema global requieren revisión de arquitectura. Las tareas numeradas son propuesta, no una API nativa de Spec Kit. Integrar plantillas oficiales conservando IDs y tests. Convergencia consume reglas explicitadas en spec/plan/tasks. Corregir brechas antes de cierre; no comprimir o borrar requisitos para terminar mas rápido.
